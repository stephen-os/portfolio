## What changed in the migration

Before this branch, posts lived flat: `content/posts/<slug>.mdx`. Images lived separately under `public/images/`. The two were linked only by a string path you had to hand-type.

Now each post owns a folder. You can drop images, code samples, or other assets next to the post and reference them with relative paths. When you delete the folder, everything goes with it.

## Code highlighting still works

Velite runs `rehype-pretty-code` at build time, so this block gets tokenized by Shiki:

```ts
import { posts } from '#site/content';

export function getRecentPosts(count = 3) {
  return posts
    .filter((p) => p.published)
    .sort((a, b) => new Date(b.date).getTime() - new Date(a.date).getTime())
    .slice(0, count);
}
```

Inline code like `getRecentPosts()` still gets the pill style.

## Authoring a new post

1. Run `mkdir content/posts/<your-slug>`
2. Drop `index.mdx` and any images inside
3. Reference images as `./your-image.png` in frontmatter or body
4. Save — `velite --watch` rebuilds, Next picks up the change

That's it. No public/ wiring, no path duplication.
